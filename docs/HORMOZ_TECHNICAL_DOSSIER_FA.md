## 1. هدف
این سند برای ثبت شواهد فنی موجود، تفکیک موارد تأییدشده از موارد نیازمند آزمون، و آماده‌سازی پرونده ارائه به پارک علم و فناوری هرمزگان تهیه شده است. این سند گواهی آمادگی عملیاتی، امنیتی یا ثبت مالکیت فکری نیست.

## 3. شواهد مشاهده‌شده
- کد بک‌اند از Node.js 22، TypeScript، Fastify و PostgreSQL استفاده می‌کند.
- اسکریپت آزمون در backend/package.json برابر `node --import tsx --test test/*.test.ts` است.
- اسکریپت build برابر `tsc` است.
- workflow با نام Backend checks در فایل .github/workflows/backend-ci.yml تعریف شده و PostgreSQL 16 آزمایشی با نام hormoz_test ایجاد می‌کند؛ سپس npm test و npm run build را اجرا می‌کند.
- تست یکپارچگی سفارش، در صورت تنظیم HORMOZ_TEST_DATABASE_URL، از نام پایگاه داده دارای test یا ci الزام می‌خواهد و ایجاد/رهگیری سفارش و عدم افشای داده خصوصی را بررسی می‌کند.
- تست health-readiness پاسخ آماده‌به‌کار و وضعیت degraded را با pool شبیه‌سازی‌شده بررسی می‌کند.
- workflow زنده .github/workflows/hormoz-live-smoke.yml مسیر سلامت، پایگاه داده پایدار، صفحات عمومی، API بازار، پاسخ نوا، صدای فارسی نوا و رد درخواست سفارش نامعتبر را بررسی می‌کند.
- بر اساس گزارش‌های قبلی Render، آخرین استقرار ثبت‌شده درگاه عمومی در 2026-11-18 و بک‌اند اصلی در 2026-11-21 موفق بوده است. این اطلاعات به‌تنهایی سلامت همه قابلیت‌ها را ثابت نمی‌کند.
- کاربر بازشدن درگاه، عملکرد گفت‌وگوی فارسی/صدای زنانه نوا و اتصال دکمه‌های خدمات به بخش‌های مربوط را گزارش کرده است.

## 4. نتایج آزمون در این نوبت
| آزمون یا بررسی | نتیجه |
|---|---|
| بازبینی package.json و دستورات test/build | انجام شد؛ دستورات موجودند |
| بازبینی workflow آزمون بک‌اند | انجام شد؛ PostgreSQL آزمایشی و build تعریف شده‌اند |
| بازبینی تست رهگیری سفارش | انجام شد؛ تست مشروط به پایگاه داده آزمایشی مستقل است |
| بازبینی تست readiness | انجام شد؛ سناریوهای سالم و degraded تعریف شده‌اند |
| بازبینی workflow زنده | انجام شد؛ مجموعه بررسی‌های زنده تعریف شده است |
| اجرای واقعی npm test در این محیط | اجرا نشد؛ محیط اجرای کد مخزن در دسترس این نوبت نیست |
| اجرای واقعی npm run build در این محیط | اجرا نشد |
| اجرای workflow در GitHub Actions | اجرا نشد؛ ابزار متصل فعلی امکان workflow_dispatch ندارد |
| آزمون زنده endpoint پایگاه داده | تأیید نشد؛ ابزار مرورگر نتوانست endpoint را دریافت کند و در لاگ درخواست‌های Render نتیجه‌ای ثبت نشد |
| بررسی امنیت کامل چندسازمانی | انجام نشده؛ نیازمند ممیزی مسیرها و آزمون تفکیک tenant است |

**نتیجه:** در این نوبت هیچ آزمون خودکار یا آزمون پایگاه داده را PASS اعلام نمی‌کنیم. تعریف شدن تست‌ها در کد، معادل اجرای موفق آنها نیست.

## 5. روش اجرای امن آزمون‌ها
آزمون یکپارچگی باید فقط با پایگاه داده آزمایشی مستقل اجرا شود؛ هرگز از DATABASE_URL تولید یا پایگاه داده کاربران استفاده نشود.

در GitHub Actions، workflow موجود Backend checks این کار را با PostgreSQL 16 و پایگاه داده hormoz_test انجام می‌دهد. اجرای موفق باید از صفحه Actions با وضعیت سبز و لاگ هر دو مرحله Run automated tests و Compile TypeScript مستند شود.

برای اجرای محلی در محیط توسعه مستقل:
```bash
cd backend
npm install
npm test
npm run build
```
برای اجرای تست یکپارچگی، متغیر HORMOZ_TEST_DATABASE_URL باید فقط به یک پایگاه داده آزمایشی مستقل با نام شامل test یا ci اشاره کند.

## 6. موارد مسدودکننده پذیرش نهایی
1. ثبت اجرای موفق workflow آزمون بک‌اند و build.
2. ثبت اجرای موفق workflow زنده و بررسی خروجی تک‌تک مراحل.
3. تأیید پاسخ مسیر /api/v1/global-orders/health مبنی بر storage=persistent.
4. ممیزی احراز هویت و مجوز تمام مسیرهای مدیریت.
5. آزمون جداسازی سازمان‌ها و جلوگیری از دسترسی متقاطع.
6. بررسی پشتیبان‌گیری، بازیابی و نگهداری داده.
7. مستندسازی محدودیت‌های سرویس‌های رایگان و برنامه پایداری سرویس.

## 7. کنترل تغییرات
در این اقدام فقط یک شاخه مستندات مستقل ایجاد شده و این فایل در آن ثبت می‌شود. هیچ فایل اجرایی، تنظیمات محیطی، کلید یا رمز، سرویس Render، پایگاه داده یا نسخه عملیاتی تغییر داده نشده است. این شاخه به main ادغام نشده است.

## 8. معرفی کوتاه پروژه
هوش هرمز یک بستر هوشمند برای هماهنگی خدمات عمومی، کسب‌وکارها و سازمان‌هاست. دستیار فارسی «نوا» ارتباط گفت‌وگویی با کاربران را فراهم می‌کند و هرمز مسئول هماهنگی خدمات، ثبت درخواست و پیگیری است. معماری هدف، چندسازمانی با جداسازی امن داده‌ها و دسترسی‌های مستقل است.

شعار: «نوا کمک می‌کند، هرمز هماهنگ می‌کند، انسان تصمیم می‌گیرد.»

اصل مأموریت: «دست گرفتن همدیگه؛ کمک کردن بدون سوءاستفاده.»
