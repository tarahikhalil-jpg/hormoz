## 3. شواهد فنی و ساختار آزمون
- کد بک‌اند از Node.js، TypeScript، Fastify و PostgreSQL استفاده می‌کند.
- اسکریپت آزمون در backend/package.json برابر `node --import tsx --test test/*.test.ts` است.
- اسکریپت build برابر `tsc` است.
- workflow آزمون بک‌اند PostgreSQL 16 آزمایشی با پایگاه داده hormoz_test ایجاد می‌کند؛ سپس npm test و npm run build را اجرا می‌کند.
- تست یکپارچگی سفارش به HORMOZ_TEST_DATABASE_URL مستقل نیاز دارد و ایجاد/رهگیری سفارش و عدم افشای داده خصوصی را بررسی می‌کند.
- تست readiness سناریوهای سالم و degraded را بررسی می‌کند.
- workflow زنده .github/workflows/hormoz-live-smoke.yml سلامت سرویس، پایگاه داده پایدار، صفحات عمومی، API بازار، پاسخ نوا، صدای فارسی نوا و رد درخواست سفارش نامعتبر را بررسی می‌کند.
- بر اساس گزارش‌های Render که قبلاً بررسی شده‌اند، استقرار درگاه عمومی در 2026-11-18 و بک‌اند اصلی در 2026-11-21 موفق بوده است.

## 5. مواردی که هنوز تأیید نهایی نشده‌اند
1. اجرای تست یکپارچگی سفارش با پایگاه داده مستقل و ایزوله test/ci.
2. ممیزی کامل احراز هویت و مجوز تمام مسیرهای مدیریت.
3. آزمون امنیتی جداسازی tenantها و جلوگیری از دسترسی متقاطع سازمان‌ها.
4. آزمون کامل تمام دکمه‌ها و گردش‌کارهای رابط کاربری در مرورگر و دستگاه همراه.
5. بررسی مستند پشتیبان‌گیری و بازیابی داده.
6. ارزیابی محدودیت‌های پلن رایگان و برنامه پایداری سرویس.
7. تکمیل مدارک مالکیت فکری، ثبت حقوقی و دامنه.

## 6. روش اجرای امن آزمون‌های باقی‌مانده
آزمون یکپارچگی باید فقط با پایگاه داده آزمایشی مستقل اجرا شود؛ هرگز از DATABASE_URL تولید یا پایگاه داده کاربران استفاده نشود. workflow آزمون فعلی در GitHub Actions برای تست‌های واحد از PostgreSQL آزمایشی استفاده می‌کند، اما لاگ این اجرا نشان می‌دهد تست یکپارچگی سفارش به دلیل نبود HORMOZ_TEST_DATABASE_URL مستقل skip شده است.

برای اجرای محلی در محیط توسعه مستقل:
```bash
cd backend
npm install
npm test
npm run build
```
برای اجرای تست یکپارچگی، متغیر HORMOZ_TEST_DATABASE_URL باید فقط به یک پایگاه داده آزمایشی مستقل با نام شامل test یا ci اشاره کند.
